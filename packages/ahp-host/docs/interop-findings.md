host across ten protocol surfaces, every finding adversarially verified. 99
confirmed, 12 refuted, 214 flows proven working between two implementations
built independently from the same spec.

Four host blockers are FIXED (see `tests/integration/test_chat_isolation.py`).
Everything below is the remaining triage list. Client-side items belong to
`agent-host-client-py`, not here.

Adjudication rule: every disagreement was decided against the vendored schema,
never against "the other peer did not like it".

## Synthesis

# Interop synthesis: agent-host-server-py ↔ agent-host-client-py

Two independently built implementations of AHP 0.7.0, driven against each other for the first time. 67 distinct defects survived adversarial verification (42 host, 24 client, 1 shared); 12 filed findings were refuted. Every item below was reproduced by a script that was actually run, and every disagreement was adjudicated against `vendor/upstream/schema/*.json`, not against "the other peer didn't like it".

**Headline honesty:** the two peers agree almost perfectly on the wire for the flows both sides implement. Nearly every host defect is reachable only from a peer that sends something this client cannot construct (schema-invalid frames, duplicate subscription lists, out-of-enum values), or from surfaces an embedder must opt into (`ResourceWatcher`, `writable=True`, `PtyTerminalBackend`). Nearly every client defect sits on its own primary API path. Four host findings are genuine blockers; the rest run minor-to-nit. Where the original filer's severity was tempered by the verifier, I use the verifier's number.

---

## 1. Ranked findings

### Host-side

**H1 — Turn cancellation is session-scoped, not chat-scoped (blocker).** `_Session.turn` is one task slot overwritten per chat and `_react` cancels it plus the session-wide `agent_session` without consulting the channel or `turnId`: cancelling chat A destroys whichever chat started last — silently, with no terminal action — leaving it permanently `activeTurn` so every later `chat/turnStarted` is rejected, while in the other ordering the addressed chat streams past its own cancel and publishes `chat/turnComplete` on a truncated answer. *Fix:* key the turn task and the provider cancel by chat URI (host.py:588, 3990, 3645-3648).

**H2 — `createChat` with `initialMessage` wedges the new chat from birth (blocker).** `_create_chat` publishes a real `chat/turnStarted` and then kicks the turn with the stub `{"type":"chat/turnStarted"}`, so `TurnRunner.run` returns on its first line: the agent never sees the message and the chat sits at `activeTurn`/status 8 forever. *Fix:* pass the action it just published, exactly as `_drain_queue` already does (host.py:2275 vs 4064).

**H3 — `createResourceWatch` escapes the filesystem jail via strict ancestors of the root (blocker, embedder-gated).** The handler checks `resolve()` + policy but never `_inside_the_jail`, so a watch rooted on any ancestor — up to `file:///` — is accepted and the poller walks it, leaking names, existence and change timing outside the served root. *Fix:* apply `_inside_the_jail` the way `_resource_request` already does at host.py:1567 and answer -32009.

**H4 — `chat/turnCancelled` is accepted with a `turnId` naming no active turn (major).** Validation checks only that *some* turn is active, so an ordinary late cancel kills the in-flight turn while the reducer no-ops, leaving state permanently claiming a turn is running. *Fix:* reject unless `turnId == activeTurn["id"]`, or gate the side effect on the reducer having applied it.

**H5 — `_react` acts on actions the reducer refused (major).** A `chat/toolCallConfirmed` aimed at a client-tool park is resolved by `toolCallId` alone, so a spec-mandated denial reaches the provider as `ToolResult(value={})` — a refusal becomes an empty success — while state records `cancelled/skipped`. *Fix:* match the park's kind and the reducer's verdict before resolving, and stop discarding `outcome.response`.

**H6 — A parked client tool is never failed when its owner disconnects (major).** `session/inputNeeded` keeps advertising a `toolClientExecution` for a client that is gone; the session is pinned at InputNeeded and the pending request survives `disposeSession`. *Fix:* fail the owner's in-flight tool calls on retire/disconnect — the SHOULD on `SessionActiveClientRemovedAction`.

**H7 — `invokeChangesetOperation` never checks the operation was declared by that changeset (major).** `_declared_scopes` returns an empty set for an undeclared id and every guard is `if declared`, so a missing membership check *disarms* target validation — reachable on the shipped demo, where `ahs-commit` is deliberately gated out of the published list and runs anyway. *Fix:* reject ids absent from the changeset's current `operations`; treat "undeclared" as refusal, not licence.

**H8 — Changeset operations stay `disabled` forever (major).** "Is a turn in flight" is sampled once at publish time and never re-evaluated, so a provider publishing from inside its own turn — the only thing it can do — greys every control for the life of the session. *Fix:* re-emit `changeset/operationStatusChanged` on turn start and turn end.

**H9 — The auto-confirming `chat/toolCallReady` omits the required `invocationMessage` and drops `toolInput` (major).** From a `streaming` source the reducer takes both from the ready action, so everything the provider streamed about the call is nulled at the moment it is confirmed. *Fix:* restate both on that frame, as `confirm_tool_call`/`run_client_tool` already do (turn.py:190-216).

**H10 — `toolInput` is published on `chat/toolCallStart`, which has no such field (major).** Combined with H9, no non-confirming server tool — including the host's own `!command` — ever shows its input. *Fix:* carry it on the ready action where the schema puts it.

**H11 — Both `TurnSink` streaming methods are no-ops in the mode the host uses them (major).** `tool_call_output` before confirmation is dropped (`contentChanged` requires `running`, which the plain path only reaches at completion) and `tool_call_delta(invocation_message=…)` after confirmation is dropped (`delta` requires `streaming`) — the shipped `EchoProvider(confirm_tools=True)` does exactly the latter. *Fix:* transition to `running` from `tool_call_output`; stop using `delta` for progress on a running call.

**H12 — A repeated URI in `reconnect.subscriptions` multiplies every replayed envelope (major).** A schema-valid request with N copies returns N copies of each missed envelope with the same `serverSeq`, corrupting chat text through a conformant mirror and amplifying a 50 KB request into a 62 MB response. *Fix:* dedupe order-preservingly in `Sequencer.replay` and `Host._reconnect`.

**H13 — `resourceWatch/changed` emits `created`/`changed` where the closed enum is `added|updated|deleted` (major).** A conformant client sees only deletions; a validating one rejects two thirds of the stream. *Fix:* rename in `_diff` — and in the type comment and the host test that pins the wrong literal.

**H14 — A watch rooted at a single file never reports anything (major).** `_scan` is `os.walk(root)`, which yields nothing for a file, so an explicitly specified case creates a healthy-looking, permanently dead watch. *Fix:* stat the file directly when the root is not a directory.

**H15 — Watches created but never subscribed are never released (major).** Release happens only on `channel_unobserved`, which cannot fire without a subscriber, and connection teardown never touches `self._watches`; channels, watch entries and strong refs to dead connections accumulate. *Fix:* drop this connection's watch channels in the read-loop `finally`, beside `unsubscribe_all`.

**H16 — A failed `ifMatch` write creates the file it refused to write (major).** `O_CREAT` precedes the etag comparison, so a conditional write to an absent path leaves a 0-byte file, returns Conflict, and permanently breaks the subsequent `createOnly` retry. *Fix:* omit `O_CREAT` when `if_match is not None`.

**H17 — An unrecognised or non-string `resourceWrite` mode silently truncates (major).** Any unknown value falls through to a full overwrite and reports success — the most destructive of the three modes chosen as the fallback. *Fix:* -32602, as malformed `data` already is.

**H18 — `resourceRead` has no size cap (major).** One unprivileged read of a 64 MiB file drove host RSS 29 MB → 970 MB out-of-process (4×–14× the file), so any served directory containing a video or disk image is an OOM lever for a peer that has only completed `initialize`. *Fix:* bound against `ResourceInfo.size`, which the host already computes one line earlier.

**H19 — `resourceWrite` cannot write through a symlink that read/resolve follow, and calls it NotFound (major).** The final component is opened `O_NOFOLLOW`, so ELOOP becomes -32008: a present, readable, resolvable file reports as absent, read-modify-write is impossible on symlinked files, and an out-of-jail link's honest -32009 is downgraded. *Fix:* follow for writes (the containment walk is already symlink-safe) or refuse with -32009.

**H20 — `root/sessionSummaryChanged` can never clear a field (major).** The diff runs only over keys present in the new projection while the baseline is overwritten, so a spec-shaped cached list keeps `activity: "Echo Tool"` on an idle session forever. *Fix:* diff over the union and clear with explicit `null`, which the upstream corpus already uses.

**H21 — `RootState.terminals` goes stale after `terminal/titleChanged` and `terminal/claimed` (moderate).** The catalogue is republished only on create/reap/dispose, so the root list reports the wrong owner — the field a client uses to decide whether to offer an input box. *Fix:* republish from `_react` for those two actions.

**H22 — `disposeChat` mid-turn strands the turn and its input request (moderate).** The channel is dropped without cancelling the turn, so a parked confirmation keeps the session at InputNeeded with an unanswerable request on a chat that no longer exists, leaked past `disposeSession`. *Fix:* cancel the turn and retract its `inputNeeded` entries before `drop_channel`.

**H23 — A side chat cannot be sourced from the source chat's active turn (major, narrow).** `_chat_origin` validates the `turnId` through `_copy_turns`, which searches completed turns only — refusing the primary side-chat use case, which the schema explicitly specifies. *Fix:* resolve a `sideChat` turnId against `activeTurn` too (fork is correctly completed-only).

**H24 — Client tool-call actions missing schema-required fields are accepted and rebroadcast (major, shared).** No shape validation, so a `turnId`-less confirmation is sequenced, fanned out and no-ops in every reducer while the tool runs; omitting `approved` makes state say `cancelled` while the provider is told accept. *Fix:* validate required fields and echo a `rejectionReason` — the mechanism exists and would have caught three client blockers at the boundary.

**H25 — `chat/toolCallComplete` is accepted from a client that does not own the call (moderate).** No comparison of the contributor's `clientId` to the dispatching connection, so another window's payload is attributed to the owner. *Fix:* add the contributor check the schema's SHOULD asks for.

**H26 — -32005 data uses `supportedProtocolVersions`; the schema requires `supportedVersions` (moderate, both sides).** The shared emitter writes the wrong key and this client reads the wrong key, so the pair agrees with itself and drops the version list against any conformant peer, in both directions. *Fix:* rename at `agent_host_protocol/errors.py:126` and `agent_host_client/client/errors.py:184` — and unpin it from `test_host_end_to_end.py:131`.

**H27 — A channel reported in `reconnect.missing` stays server-side subscribed (minor).** Registration precedes classification, so the host says "drop this" and keeps delivering it if the URI is reused; empty subscriber sets are never removed. *Fix:* classify first, register survivors only, delete empty keys.

**H28 — A `session/titleChanged` with no title makes the host serve state that fails its own schema (minor).** `SessionState` and every `SessionSummary` lose the required `title` and the cached catalogue keeps the old one (same clearing hole as H20); `null`/`7` pass through untouched. *Fix:* reject a non-string title or fall back to `_DEFAULT_SESSION_TITLE`.

**H29 — `resourceRequest(write=true)` is granted by a read-only host that then denies every write (minor).** The check is a structural `isinstance(..., WritableResourceProvider)`, satisfied regardless of `writable=False` — and that is the shipped `--serve-directory` default. *Fix:* consult the flag.

**H30 — A negative `resourceWrite position` NUL-pads past EOF or leaks a raw OSError (minor).** `append` reports success after injecting five NUL bytes; `insert`/`truncate` surface EINVAL as -32603 with the errno string. *Fix:* -32602 (the high end is already clamped).

**H31 — A changeset's catalogue entry is published once and never refreshed (minor).** Label, description and `capabilities.review` changes never reach the client, and the review gate reads the *updated* entry — so the host accepts review for a changeset the client believes is unreviewable, and vice versa. *Fix:* re-emit when the entry differs.

**H32 — A host-originated `changeset/filesReviewChanged` is not remembered (minor).** Only the client-dispatch path writes `session.reviewed`, so the host's own tick is wiped by the next republish and no public API can record one. *Fix:* record host-originated review too.

**H33 — A range-scoped operation target is accepted without the required `range` (minor).** The embedder's handler raises `KeyError` and the caller gets -32603 for an unambiguous caller mistake. *Fix:* validate the variant and answer -32602.

**H34 — `createTerminal` without `name` publishes a `TerminalState` with no `title` (minor).** The required field is omitted, failing the whole `Snapshot.state` union, while the root catalogue substitutes `"Terminal"` — two host states disagreeing about one terminal. *Fix:* seed the same fallback at registration.

**H35 — A non-string entry in `protocolVersions` returns -32603 with a raw Python `TypeError` (minor).** Peer-controlled input reaches `_SEMVER.match` unguarded, so schema-invalid params become "the host has a bug" plus a leaked type name. *Fix:* validate element types beside the existing non-empty-array check.

**H36 — A fork source with no `turnId` is accepted and publishes a `ChatOrigin` missing its required `turnId` (minor).** *Fix:* reject, or resolve to the last turn and publish that.

**H37 — `listSessions` silently ignores a non-integer `limit` (nit).** The gate is `isinstance(limit, int)` against a schema-typed `number`, so `3.0` means unbounded while `true` is honoured as 1. *Fix:* floor a numeric limit.

**H38 — The seeded title overshoots its own 60-char cap when the first word is longer than the limit (nit).** A pasted URL yields 62 characters. *Fix:* budget for the ellipsis on both branches.

**H39 — `resourceResolve` with `followSymlinks=false` still canonicalises a symlinked parent (nit),** where the schema says the returned URI equals the requested one. *Fix:* echo the requested URI when not following.

**H40 — `source.selection` is never validated (nit).** `{}` and `{"text": 123}` are stored and republished into `ChatOrigin`, where both are hard schema violations. *Fix:* validate it.

**H41 — Duplicate `createTerminal`/`createChat` answer -32003 "Session already exists" (nit).** The shared helper hard-codes the session code and wording for a flat channel namespace. *Fix:* channel-shaped message, -32010 for non-session collisions.

**H42 — The `changes` roll-up is written straight into `SessionState` with no action (nit).** Already-subscribed clients never converge while later subscribers get a key `SessionState` does not define. *Fix:* keep it out of the channel's state, or publish it as an action.

*(Also confirmed but not conformance defects, recorded so nobody re-files them: `disposeTerminal` is not claim-gated — correct at the policy layer, but the module docstring should say so; `terminal/titleChanged` payloads are not type-checked — no MUST exists and the blast radius stops at the channel; `SessionState.status` never returns to Idle after an input request — an upstream reducer gap, not this host's.)*

### Client-side

**C1 — `connect()` never returns when the handshake is permanently refused (blocker).** `_supervise` reaches `HostState("failed")` and returns without setting `_connected` or `_shutdown`, so the default `start(wait=True)` is parked on an unsatisfiable await: -32005, an exhausted budget, or `reconnect=False` all deadlock with no exception. *Fix:* release `_await_connected` on both terminal transitions and raise the classified error.

**C2 — A failing turn never terminates `TurnStream` (blocker).** `TurnFailed` is bound to `chat/turnFailed`, which exists nowhere in the spec, so the host's schema-valid `chat/error` decodes as `UnknownEvent` and `await prompt()` blocks 300 s then raises `TimeoutError`. *Fix:* key it on `chat/error`, and populate `reason` from `action["error"]["message"]` (nothing ever sets it).

**C3 — `Chat.cancel()` omits the required `turnId` and `duration` (blocker).** The reducer's `_end_turn` matches on `turnId`, so the cancel no-ops on both peers while the host still kills the provider: the chat is wedged and every later turn is rejected "a turn is already active". Found independently on four surfaces. *Fix:* read `state["activeTurn"]["id"]` — the value is already in hand.

**C4 — Every tool-call action the client emits omits the required `turnId` (blocker).** Five sites (`approve`/`deny`, `ClientToolHost.execute`, `confirm_tool`, `confirm_result`): confirmations no-op while the host runs the tool, live tool output is discarded, a denial renders as "ran and failed", a completed client tool records `cancelled/skipped`, and `confirmed` back-fills to "nobody was asked". *Fix:* carry `turnId` everywhere, add the required `confirmed`, rename `optionId`→`selectedOptionId`, and read the id from `entry["toolCall"]["toolCallId"]` (the two `confirm_*` paths currently send `null` and hang the turn).

**C5 — The client can never answer an elicitation (blocker).** All four answer paths send `chat/inputAnswerChanged` with a plural `answers` map and a `kind` field — invalid as either action — and `chat/inputCompleted`, the only action that resolves a request, is never sent by any code path. *Fix:* send `chat/inputCompleted` on submit and the singular per-question form for drafts.

**C6 — `StateMirror` applies another client's rejected action (blocker).** The `rejectionReason` check is gated on `origin.clientId == self._client_id`, so a foreign rejected envelope is reduced and an observer's transcript diverges from the host permanently — reproduced in stock configuration. *Fix:* honour `rejectionReason` on every envelope; keep the `own` gate for retiring pending only.

**C7 — The client's resource server is broadly non-conformant (blocker, largest cluster in the run).** `content` where the schema says `data`+`encoding` on read *and* write (so a spec-shaped write silently zero-truncates the file and reports success); `kind` where `type` is required on list/resolve (so plugin expansion returns no children); `resourceMkdir` creates the parent, not the target (depth-1 is a pure no-op) and reports success; `resourceRequest` answers denial with a successful `{"granted": false}` and ignores the read/write flags entirely; copy/move ignore `failIfExists`; missing `uri` answers NotFound rather than InvalidParams; `mtime` is an integer where ISO 8601 is declared. *Fix:* one pass over `serve/resources.py` against `commands.schema.json`.

**C8 — `AhpClient.create_chat()` cannot emit a valid `createChat` frame by any spelling (blocker for the typed surface).** `_scoped` forces the positional into `channel` and never sets the required `chat`; every workaround collides with the parameter's own name. *Fix:* `create_chat(session, chat, **extra)`.

**C9 — Pending actions survive a reconnect but are never re-sent (major).** A pending entry whose frame died in the write loop is kept forever under the default policy, so `optimistic` — the state the library says to render — shows a phantom turn and `IN_PROGRESS` through subsequent successful turns. *Fix:* implement the re-send its own ADR specifies, or clear survivors.

**C10 — Approval policies are dead against a conformant host (major, fails open *and* closed).** `tool_name` and `annotations` are read off `chat/toolCallReady`, which declares neither: `auto(allow=…)` silently denies, `auto(deny=…, otherwise=True)` silently *runs* a denied tool, and `approvals="reads"` equals `deny_all()`. *Fix:* resolve both from the mirror.

**C11 — The client answers auto-confirmed tool calls, breaking client-contributed tools (major).** Every `chat/toolCallReady` becomes an approval question regardless of `confirmed`, so the stock drain resolves the host's parked execution before any executor runs: the tool never executes and the agent receives `{}`. *Fix:* treat a ready action carrying `confirmed` as a state transition.

**C12 — `TurnStream` omits the required `startedAt` and `message.origin` (major).** Every turn this client starts is persisted for every subscriber with `startedAt: null`. *Fix:* stamp both in `_start`.

**C13 — A rejected `chat/turnStarted` is yielded as a plain `TurnStarted`, then the stream hangs (major).** `__anext__` never inspects `rejectionReason`, so the caller believes the turn started and waits out the idle timeout; `ChatWatch` has the same blind spot. *Fix:* treat a rejection of this stream's own turnId as terminal, carrying the reason.

**C14 — Four of fourteen `_BY_TYPE` keys name actions that do not exist (major).** Besides C2: `chat/reasoningDelta` (so reasoning arrives as `UnknownEvent` and `Reasoning` is unreachable), `chat/titleChanged`, `chat/toolCallResultReview` (the real signal is `toolCallComplete` + `requiresResultConfirmation`, so a result review hangs the turn); `chat/toolCallDelta` and `chat/toolCallContentChanged` are unmodelled entirely. *Fix:* reconcile the table against `ACTION_TYPES` — a generated cross-check catches all six.

**C15 — `ResourceRouter` cannot be passed to `connect(resources=…)` (major).** It implements `__call__`, not `handle`, so the documented multi-mount primitive answers -32603; the `server_request_handler` passthrough always collides, and the manual escape hatch is silently wiped by the first reconnect. *Fix:* add a `handle` alias or widen the parameter.

**C16 — `create_session(tools=[…])` publishes tools the front door can never execute (major).** `ClientToolHost` is never wired into `connect()`. *Fix:* route client-contributed calls to an executor built from the same `tools=` list.

**C17 — The elicitation event is unusable even before C5 (major).** `request_id` reads a field `chat/inputRequested` does not have (always `""`), there is no accessor for the message or questions, and `_existing_answers` scans a `ChatState.inputRequests` field that does not exist, so the documented merge-don't-clobber never fires. *Fix:* read `request.id`, expose the request, read drafts from the response part.

**C18 — The cached session list ignores `root/sessionSummaryChanged` (minor).** `_track` handles add/remove and drops the third catalogue notification, so `session_summaries` is stale until the next reconnect. *Fix:* merge `params.changes`.

**C19 — Reconnect replay re-publishes envelopes the mirror discards as stale (minor).** `_absorb_reconnect` throws away the `ApplyOutcome`, so a consumer re-renders an entire finished turn. *Fix:* gate the publish on `outcome is not STALE`.

**C20 — A disposed session stays in the subscription set and the mirror (minor).** `session.state` reports `lifecycle: "ready"` for a session its own `dispose()` just removed; heals on reconnect via `missing`. *Fix:* drop the URI and its chats in `_track`.

**C21 — Gap detection is per-channel over a host-global counter (minor).** Every interleave of two subscribed channels reports a false `SequenceGap` (3 reports for 1 real loss), and `RESEED` marks byte-identical channels stale after one turn. *Fix:* scope to the global cursor, gate on full coverage, or default to IGNORE.

**C22 — A rejected envelope never advances `channel.last_seq` (minor),** so the next envelope always looks like a hole. *Fix:* record `last_seq` for every gap-checked envelope.

**C23 — `shutdown()` leaves the writer task pending after a transport drop (minor)** — one leaked task per reconnect, and on the malformed-frame path the transport is never closed either. *Fix:* make the early return skip the state transition, not the cleanup.

**C24 — A refused `subscribe` leaves the channel bound and tracked (minor);** `mirror.state(uri)` then raises `AttributeError` after any dispatch. *Fix:* the conditional rollback `AhpClient.subscribe` already implements.

**C25 — `terminalCommandPrefix`, `serverInfo` and `telemetry` are discarded by the high-level client (minor).** The `!` shorthand works but no `connect()` caller can discover it. *Fix:* retain and expose.

## 2. Coverage

### Proven to work between two independent implementations

Adjudicated on what the host *publishes* versus what the client *expects* — reducer agreement was explicitly discounted, since both peers import `agent_host_protocol`.

- **Handshake and resumption.** `ping` before `initialize`; the full version-negotiation matrix including -32005/-32602 paths; `InitializeResult` and every `Snapshot` schema-valid; pre-`initialize` command gating; subscribe/unsubscribe in all result shapes; `reconnect` on both the replay and snapshot arms, including replay-budget overflow degradation, unknown-clientId fallback to a fresh `initialize`, and `missing` for disposed and policy-revoked channels; supervised reconnect converging byte-identically; keyset pagination correct under concurrent mutation; the subscribe/`fromSeq` ordering boundary under load.
- **Turns.** Full streaming lifecycle and event ordering; text fidelity byte-exact across unicode, astral planes, 200-delta turns and empty turns; part segmentation preserving order; `usage`; error settling; well-formed cancellation including partial-text and producer-supplied duration; overlapping-turn rejection; `ChatWatch(from_start=True)`.
- **Tool calls (host side).** Plain and confirmation paths; `session/inputNeeded` mirroring and retraction; `contentChanged` replace semantics; parameter streaming; `editedToolInput` round trip; duplicate-answer arbitration; stale-confirm rejection; cancellation while parked; client-contributed tools once the payload carries `turnId`.
- **Elicitation (host side).** All six question kinds and all five answer value kinds; url-only and bare requests; accept/decline/cancel; cross-client draft merge; answering from a session-only subscriber; two concurrent parked requests; connection drop while parked; hostile payloads absorbed without killing the host.
- **Sessions and multi-chat.** createSession matrix and error codes; bring-up ordering; title-seeding rules; isRead/isArchived; the chats catalogue; fork semantics including fork-of-fork; disposeSession; summary partial updates; second-client broadcast; capability gating per sub-flag; queued-message FIFO drain, reorder and cancel; two chats streaming concurrently with isolated transcripts.
- **Changesets.** Catalogue/state/file/operation schema conformance; publish ordering; git-accurate file lists and per-file diffs; content-store reads with encoding negotiation and store immutability; review round trip and persistence; operation status machine including the error arm; real git effects; malformed-invocation rejection.
- **Terminals.** PTY round trip, resize, title, exit codes; claim gating and transfer; session claims; full OSC 633/133/1337 handling including escape sequences and UTF-8 codepoints split across reads; reconnect with claim survival; `!command`; the dispatchability gate against 16 hostile payloads; host state byte-identical to the client mirror.
- **Resources.** resolve/list/read including symlinks and encodings; jail containment; all three write modes; `createOnly`/`ifMatch` on existing files; copy/move/delete; watch scoping, includes/excludes, coalescing, lifecycle and per-connection cap; concurrent atomic appends; correct client error-code mapping; all 66 client-emitted param frames schema-valid.
- **Errors and mirror convergence.** The full code taxonomy; six distinct rejection paths with correct originator revert; mirror versus host across five channels at serverSeq 67 with zero non-clock differences; mid-turn subscribe landing exactly on the boundary; both reconnect arms converging.

### Not reachable, and why

1. **Step-up auth** (`authenticate`, `chat/toolCallAuthRequired`, the `AuthRequired` notification, MCP OAuth). The client has the command and an `InputResponder.authenticate`, but no probe provider raises an auth-required tool call.
2. **OTLP telemetry and `root/progress`.** The client decodes all four into events; nothing made the host emit them or subscribed to an `ahp-otlp://` template.
3. **MCP apps** (`capabilities: {mcpApps: {}}`, `ahp-mcp-ui`) — advertised in the handshake, never exercised.
4. **Session config and customizations** beyond the plugin-expansion path — `resolveSessionConfig`/`sessionConfigCompletions` were error-probed only.
5. **Result confirmation.** `ActionTurnSink.tool_call_completed` has no `requiresResultConfirmation` parameter, so the host cannot produce the state; it was only testable behind a shim.
6. **Steering-message injection.** The host deliberately leaves consumption to the provider and no provider hook exists, so the round trip is unbuildable today.
7. **Multi-user policy over the wire.** Almost everything ran under `LoopbackSingleUserPolicy`; the ownership findings used hand-written policies rather than the shipped `OwnedSessionPolicy` in a realistic two-principal deployment.
8. **Client ergonomics for four whole surfaces.** Multi-chat, changesets, terminals and resource watches have no typed client API, so they were driven through `client.protocol.request` / `client._runtime`. What is proven there is the host's wire behaviour, not the client's. Note the correlation: the surfaces where the client *does* have an API are where essentially all client defects are.
9. **Transport realism.** Nearly everything ran over `memory_pair`; only the handshake-refusal repro used real WebSockets. Frame limits, backpressure, TLS and `--connection-token` remain covered by the TypeScript interop test, not this one.
10. **0.6.0 behaviour.** Negotiation *to* 0.6.0 was verified, but no surface was driven while pinned there, so version-gated action availability (`ACTION_INTRODUCED_IN`) is untested between the peers.

## 3. Proposal: `tests/interop/test_py_client.py`

### Shape

Follow `test_real_client.py` structurally, drop everything it needs only because the TS client is a subprocess. The Python client is an import, so: no `driver.mjs`, no sockets, no JSON report parsing, and — crucially — assertions can compare `host.sequencer.state_of(uri)` against `client.mirror.confirmed(uri)` directly, which the TS test cannot do cheaply.

```python
"""Interop: the real Python client (agent-host-client-py) against our host.

Skipped unless the sibling client is installed:  uv pip install -e ../agent-host-client-py
Where the TS driver proves we can talk to the reference client, this proves we
can talk to a client that VALIDATES -- it has its own mirror, its own pending
queue and its own opinion about every shape we publish.
"""

import asyncio, importlib.util, os
import pytest
from agent_host_protocol.transport import memory_pair
from agent_host_server.core import Host, LoopbackSingleUserPolicy
from agent_host_server.provider import EchoProvider

pytestmark = [pytest.mark.py_interop, pytest.mark.anyio]

SETUP = "needs the sibling client: uv pip install -e ../agent-host-client-py"
_HAVE = importlib.util.find_spec("agent_host_client") is not None
if os.environ.get("AHP_INTEROP_REQUIRED") and not _HAVE:
    raise RuntimeError(f"AHP_INTEROP_REQUIRED is set but the client is missing: {SETUP}")
requires_client = pytest.mark.skipif(not _HAVE, reason=SETUP)


@pytest.fixture
def anyio_backend() -> str:
    return "asyncio"


@contextlib.asynccontextmanager
async def paired(host, **connect_kwargs):
    """Host + real client over memory_pair, with a hard deadline on the body."""
    from agent_host_client import connect

    client_t, server_t = memory_pair()
    serve = asyncio.create_task(host.serve(server_t))
    try:
        async with connect(transport=client_t, **connect_kwargs) as client:
            yield client
    finally:
        serve.cancel()
        await host.aclose()
```

Two conventions, both load-bearing:

- **Register the marker.** `--strict-markers` is on; add `py_interop: requires the Python client (agent-host-client-py)` to `[tool.pytest.ini_options] markers` rather than reusing `interop`, so `-m "not interop"` keeps meaning "no Node".
- **No sleeps, ever.** Every wait is `await` on a specific event or frame. Where a probe needed a race (reconnect ordering, dispose-before-reconnect), use a *gated* `transport_factory` — an `asyncio.Event` the test opens — never a timer. Wrap each test body in `asyncio.wait_for(..., 15)` so a regression fails instead of hanging CI. `EchoProvider(delay=0.0)` throughout, except where a test genuinely needs an in-flight turn, in which case gate on the first streamed event rather than a delay.

### Tier 1 — permanent smoke, must never regress (4 tests, <2 s total)

1. **`test_python_client_drives_a_turn_end_to_end`** — connect → `create_session` → `prompt` → assert the event class sequence `[TurnStarted, ResponsePartAdded, Delta…, Usage, TurnCompleted]` and the echoed text. The direct analogue of the TS test.
2. **`test_mirror_matches_host_after_a_busy_session`** — the single highest-value test in the file. Two turns (one with an approved tool call, one cancelled with a *correctly formed* cancel), a second chat, then diff every channel `host.sequencer.state_of` vs `client.mirror.confirmed` ignoring `modifiedAt`, and assert `mirror.last_server_seq == host.sequencer.server_seq`, zero un-retired pending entries and zero buffered envelopes. This is what a second, independent mirror buys you over the TS driver.
3. **`test_doctor_probe_passes`** — `agent_host_client.doctor.diagnose(transport)` reports 11/11. One line; catches whole-handshake regressions.
4. **`test_supervised_reconnect_resumes_and_converges`** — `transport_factory` that drops once; assert the replay arm was taken, state is `connected` at generation 2, mirror equals host, and a turn still runs.

### Tier 2 — regressions for the host defects found here

Each is a one-screen test; each currently fails. Land them as `pytest.mark.xfail(strict=True, reason="H-nn")` alongside the finding, and flip to passing with each fix — that way the suite records the finding and tells you the day it is fixed.

- **H12** replay of a duplicated `subscriptions` list contains no repeated `serverSeq`.
- **H1** cancelling chat A leaves chat B streaming, and B accepts a further turn.
- **H2** `createChat` with `initialMessage` runs the turn to completion.
- **H4** a `chat/turnCancelled` naming a foreign turnId is rejected and the live turn continues.
- **H9/H10** the auto-confirming ready action carries `invocationMessage`, and a plain server tool ends with `toolInput` set.
- **H11** `tool_call_output` before confirmation reaches the client's state.
- **H20** a cache built from `sessionAdded` + `sessionSummaryChanged` equals `listSessions` after a tool turn. Cheap, and it is the whole "spec-shaped client" contract in six lines.
- **H21** the terminal catalogue is republished after `titleChanged`/`claimed` — use a **stub** terminal backend, no pty, so it stays deterministic.
- **H8/H7** operations return to `idle` after the publishing turn ends; an undeclared operation is refused. Drive with `host.publish_changeset(...)` plus a stub handler — **no git**.
- **H3/H13/H14/H15** watch surface: an ancestor of the root is refused; change types are `added`/`updated`; a file root reports its own change; a never-subscribed watch is released on disconnect. `tmp_path` root, ~20 ms poll interval, assert by awaiting the action.
- **H16/H17/H19** `ifMatch` against an absent path creates nothing; an unknown mode is -32602; a write through an in-jail symlink either succeeds or answers -32009.
- **H26 + schema gate** validate *every* frame both directions during Tier 1 against the vendored schemas, reusing `tests/conformance/schemas.py` — and extend it to error `data` payloads, which is precisely the blind spot that let H26 ship (`schemas.py` validates actions, states and command results, never error data).

### Tier 3 — client-defect regressions: two only, both `xfail(strict=False)`

C1–C25 belong in the client repo and the host suite should not pin them. Keep exactly two here, because they are what breaks when *the host* changes shape: `await session.prompt()` against a raising provider returns a `TurnFailed` carrying the host's `errorType` (C2), and `await chat.cancel()` settles the turn (C3). Non-strict xfail so they flip to XPASS — and report — the day the client ships a fix.

### One-off probes — do not keep

- **Measurements**: the `resourceRead` RSS numbers, the 62 MB replay amplification, task-leak and GC counting, `ps` scraping. Non-deterministic and machine-dependent. Replace each with a cheap structural assertion once the fix lands ("the replay list has no duplicate `serverSeq`", "a read above `max_read_bytes` answers -32009").
- **Host-only sweeps**: the 16 hostile terminal payloads, the 15 malformed reducer actions, the pagination-cursor matrix, the negotiation matrix. Valuable, but no second implementation is involved — they belong in `tests/unit` / `tests/integration`, where several already are.
- **Anything needing git, a pty or a real socket**: keep the OSC/pty coverage in `test_terminals.py` and the git-backed changeset coverage in `test_changesets.py`. The interop file uses a stub terminal backend and `publish_changeset` directly.
- **Anything reaching into `client._runtime`, `client.mirror.bind` or monkeypatching `_BY_TYPE`**: those test client internals, not the pair. If a flow is only reachable that way, that fact is itself a client finding (C8, C16) — record it in the finding, not in a test the host repo has to maintain.

### CI note

The client is a sibling checkout, not a published package. Pin it the way `npm i --no-save @microsoft/agent-host-protocol@0.6.0` pins the TS client — install from a pinned git ref in CI, and make `AHP_INTEROP_REQUIRED` cover both interop files, so a broken install surfaces as a hard error rather than a silent skip. A skipped interop test is indistinguishable from a green one at a glance, which is the reason the existing file has that guard at all.
