### Added — secrets out of the run log (M17)

- With `RunOptions.redact` set and `keep_source` left False (new, default), the journal header stores the script and its args masked, and each child `workflow` record its source masked. The header carries `sourceSha` and `argsSha` and a workflow record `sourceSha`, always the sha256 of the real text (`engine.text_sha`; args by the canonical JSON); old readers ignore them (`JOURNAL_VERSION` stays 1). `engine.source_masked`/`args_masked` tell a masked header apart. Resuming such a run needs the real script (a different one is refused) and the same args (`has_args`); a masked child workflow is resolved from the registry again and refused if its sha256 changed, as a failing `workflow()` call. `keep_source=True` keeps the raw text. `tests/unit/test_maskjournal.py`.
- A masked journal never loses a run. After a restart `FlowSession.resume_turn` gets the real script by re-resolving the run's workflow, named by the turn's own message read back from the stored chat (ahp-host's new `ObservesChatState`), and the real args by re-parsing that message with the same parser as a new turn (`FlowSession._parse_start`); both are checked against `sourceSha`/`argsSha`, and a mismatch fails the turn with "the workflow changed since the run started" (or "the args changed ..."), never runs something else. `tests/integration/test_maskresume.py` (drain and crash over `FileSessionStore`, a secret in the script and the args, neither in either journal).
- `RunOptions.resume_source` and `resume_args` (kept out of repr and equality; `engine.NO_RESUME_ARGS` when unset; need `resume_from`): a library caller's real script and args for a masked journal, checked by sha256; on an unmasked journal `resume_args` must match. `tests/unit/test_maskjournal.py`.
- `[journal] keep_source` in flow.toml (`config.JournalConfig`, default `false`) is the provider's `RunOptions.keep_source`. `tests/unit/test_journalcfg.py`, `tests/integration/test_maskwire.py`.
- `flow run` masks with the builtin credential shapes: its journal (script and args with their sha256), `log()` lines and errors. `--args` is allowed with `--resume` (checked against the journal's sha256; `--budget` still is not), `--keep-source` keeps the text (with `--config`, it overrides `[journal] keep_source`), and `--wire-log PATH` (with `--config`) writes the in-process host's frames. `tests/unit/test_cli_mask.py`, `tests/unit/test_cli.py`.
- The sandbox masks a script's `log()` lines and its error (message, stderr, stack) with `RunOptions.redact`, and `library.FlowRun.log` masks too, so the library, the CLI and the provider all get them masked. `tests/unit/test_maskjournal.py`.
- Wire logs the flow host builds are masked by the run's `Redactor`: `python -m ahp_host_flow --wire-log PATH` (`build_host(wire_log=)`) and `flow run --config --wire-log PATH` pass it as ahp-host's `Host(wire_log_mask=)`. The proving test: a secret in the args and in the script text appears in neither the journal nor the wire log of a hosted run. `tests/integration/test_maskwire.py`.

### Added — durable worker chats (M17)

- Named chats (`opts.x.chat`) are persisted in the flow resume state and rebuilt after a restart: `dispatch.DurableWorkers` (`named`, `inflight`, `restored_named`, `restored_inflight`; `to_json`) is shared by the run's `RunEntry.durable` and its `ProviderDispatcher(durable=...)`. At the end of each turn the dispatcher records the chat's provider, worker chat, title, config, folder and, on a `ResumableAgentProvider`, the inner session's resume state (`namedChats`, camelCase keys, all optional; `RESUME_STATE_VERSION` stays 1). After a restart the first call naming the chat resumes its session in the same worker chat (log: `... resumed its session on provider ... after the restart`); otherwise the chat is recreated with a log line (`... was recreated after the restart; ...`), as before. A `resume_session` failure logs and recreates. `_parse_runs` reads `namedChats` and `inflight` and drops malformed items with a warning, keeping the run; a second restart before the call is reached keeps the record. `tests/unit/test_durnamed_state.py`, `tests/integration/test_durnamed.py`, with `ResumableHoldProvider` (`tests/flow_fakes.py`).

- A cut-off unnamed call on a provider that resumes sessions and turns is resumed in place: `ProviderDispatcher` records `{provider, turnId, innerState}` in `DurableWorkers.inflight` when the turn starts (schema-less, no worktree, `ResumableAgentProvider`; dropped when the call ends) and, after a restart, resumes the session on the old worker chat and calls `resume_turn` instead of sending the prompt again (log: `... resumed the turn the restart cut off on provider ... in place (...)`). A session that cannot resume turns is sent the prompt as a new turn, and a failed `resume_session` falls back to a new worker chat; schema and worktree calls are dispatched again as before. `tests/integration/test_durinflight.py`.
- `engine.DispatchHandle.worker_chat` (and `StartRecord.worker_chat`, the journal `started` handle's `workerChat`): an in-process call's resumable worker chat, in a field of its own instead of `session`; the in-process dispatcher reads only it and the fleet and remote dispatchers only `session` (`fleet.reattach_session`). `tests/unit/test_handle_kinds.py`.
- A worker turn is kept in `inflight` only when a host shutdown cut it off: an abort (`ProviderDispatcher(aborted=)`, the run's `AbortSignal`), a skip, the idle watchdog or a stop the run made (budget, quota, wall time, call timeout: `stop_cause`) drops it. `tests/integration/test_durinflight.py`.
- A named chat that is recreated after a restart says why: it ran on another provider, the provider cannot resume sessions, it recorded no session state, or its worker chat is gone. `tests/integration/test_durnamed.py`.
- `tests/flow_fakes.py`: `ResumableHoldSession` resumes turns (answering `RESUMED_IN_PLACE`), `TurnlessHoldSession` does not, and `ResumableHoldProvider`'s `resumes_turns`, `records_state` and `fail_resume` flags make the negative cases (no state recorded, no `resume_turn`, `resume_session` failing), each tested in `tests/integration/test_durinflight.py`.

### Added — per-call sandboxed hosts (M17)

- `providers.<name>.launch` ('module:function', an async factory) and `per_call` (`ProviderConfig.launch`, `.per_call`): a remote provider whose host is started by your own code instead of dialed at a `url`. `launch` is exclusive with `load`, `via` and `url`, and refuses `token_file`; `per_call = true` needs `launch`. `engine.remote` has `LaunchRequest` and the `Launcher` type (request -> transport and teardown), and `RemoteSpec.launch`/`per_call`; `loading.load_launcher` imports the factory. `tests/unit/test_launchcfg.py`.
- `ClientDispatcher` launches, dials, runs and tears down a host per call: with `launch` alone the host is started on first use and closed by `aclose`; with `per_call` every call gets its own, launched with the call's folder (`opts.x.cwd`) and the client tools and torn down after it on every path (done, failed, skipped, aborted), a launch or dial failure being `unavailable` (transient). A call a restart cut off is run again on a new host (logged), not reattached. `provider.remote_for` loads the launcher (a bad import is `unavailable`). `tests/launch_fakes.py`, `tests/unit/test_percall_engine.py`, `tests/integration/test_percall.py`.
- A per-call host is torn down when the call is skipped or aborted while its client still connects, or while that client closes (one shielded teardown); both used to leak the launched host now and then.
- The README's launcher publishes the container's port on `127.0.0.1` and starts `python -m ahp_host_acp --bind 0.0.0.0 --token-file ...` inside it (ahp-host-acp's new off-loopback bind), not `--network host`; it says a shared (non-`per_call`) launch gets no folder or client tools. `tests/docs/test_sandboxhost_readme.py` runs the launcher's imports and checks every ACP-host flag it passes against that CLI's parser.

### Fixed — M16 review

- `Scheduler()` no longer needs a running event loop: the loop is taken lazily, and only with a `wall_budget`, at the first check inside the loop (the wall clock and its timer start there). The synchronous `tests/unit/test_scheduler.py` tests pass again.
- A fleet call the run itself stops (a live stop on budget, wall time or quota, or `call_timeout`/`opts.x.timeout`) now stops its node session instead of leaving it running as if the host were stopping. The Scheduler sets the call's `StopCause` (`engine.StopCause`, `engine.stop_cause()`) before it cancels, and `StepDispatcher.run_agent` puts its timeout scope on it; only a cancellation with no abort and no stop cause detaches. `tests/integration/test_fleet_stopcause.py`.
- A live-stopped call's main-chat `agent` tool call is completed as an error step (`stopped: <reason>`, "agent() stopped") instead of staying `running`. `tests/integration/test_livestop_hosted.py`.
- The usage of a failed attempt is counted: each dispatch attempt reports into a usage slot of its own (`engine.begin_usage_attempt`/`end_usage_attempt`, used by `RoutingDispatcher`), the Scheduler sums the slots, and a finished call takes per counter the larger of its result and that sum. An exhausted `retry_empty` and a primary that failed before its fallback now reach the budget, the journal record and the quota. `ProviderDispatcher` and the fleet dispatcher report a failed attempt's final usage. `tests/unit/test_attempt_usage.py`, `tests/integration/test_retryempty.py`, `tests/integration/test_fallchain_dispatch.py`.
- `concurrency = "probe"`: callers that arrive while the probe runs wait for it (they used to go through with no limit), and a first caller cancelled mid-probe leaves the probe to the next caller instead of losing it. `tests/unit/test_provslots.py`, `tests/integration/test_provslots_probe_hosted.py` (end to end through flow.toml).
- ACP: an input that ahp-host-acp marks as its context gauge (`acpUsage.inputGauge`) counts 0 input tokens, and `acpUsage.cost`, the ACP session's running total, is taken as a delta per call, so later calls on a reused session (a named chat) count only what they add. `tests/unit/test_budgetctr_usage.py`, `tests/integration/test_flowlimits_hosted.py`.
- A live check with nothing in flight neither logs nor marks a stop (no more "stopping 0 agent() call(s) in flight"). Schema failures and non-JSON results are journaled with kind `failed`. `tests/unit/test_quota_ledger.py`, `tests/unit/test_errkind_journal.py`, `tests/unit/test_errkind_table.py` (every `ERROR_TABLE` row classifies as listed).
- An in-process call's `AgentResult.usage` carries `cache_read_tokens` beside `input_tokens` and `output_tokens` (for the input and cache budgets); `tests/integration/test_provider_dispatcher.py` expects the new key.
- `idle_timeout` is accepted on fleet providers (it used to be an unknown key there); `tests/unit/test_flow_toml.py` now checks its value instead.

### Added — fallback chain (M16)

- `providers.<name>.fallback` (`ProviderConfig.fallback`, all kinds) and `routing.rules[].fallback` (`RoutingRule.fallback`): providers tried in order when a call fails as `unavailable`, `rate_limited`, `timeout`, `empty` or transient `failed`. Validated at load (unknown names, a provider listing itself, `fallback cycle: a -> b -> a`). `routing.fallback_chain` expands the chain; `RoutingDispatcher.run_agent` walks it, logging `agent() #n: fell back from a to b (kind)`, skipping fleet and remote candidates for `opts.x.chat`/`attach` calls, and attempt-numbering tool call ids across fallbacks and `retry_empty`. Resume keys keep the routed provider. A later dispatch report writes another `started` record whenever it names another place than the recorded one (a fallback's provider, or a retry attempt's chat or node session on the same provider), so a reattach after a cut-off attempt points at the live one; `load_journal` keeps the last. Before, a single report was written per call; `tests/unit/test_scheduler_journal.py` now expects one record per distinct handle. `tests/unit/test_fallchain_config.py`, `tests/integration/test_fallchain_dispatch.py`.

### Added — provider concurrency (M16)

- `providers.<name>.concurrency` (`ProviderConfig.concurrency`): an integer >= 1 for any kind, or `"probe"` for an in-process provider. New top-level module `limits.py`: `ProviderSlots` (a semaphore with a changeable limit, shared across runs; `on_busy` halves a non-explicit limit, never below 1), `probe` (two minimal turns in parallel on two fresh sessions; single slot when the second's first event comes after at least `PROBE_RATIO` = 0.8 of the first turn's length) and `ProviderSlotsRegistry` (`FlowProvider.provider_slots`, one entry per provider name, probed once at first use). `RoutingDispatcher(slots=)` holds the slot around each dispatch attempt, inside the run's own Scheduler slot; a `rate_limited` error, or a transient `unavailable` one, calls `on_busy`. `tests/limits_fakes.py` (`SingleSlotProvider`, `ParallelProvider`), `tests/unit/test_provslots.py`, `tests/integration/test_provslots_probe.py`.

### Added — heartbeat (M16)

- `[limits] heartbeat` (seconds > 0, default 30; `LimitsConfig.heartbeat`): while at least one `agent()` step is in flight, a session publisher that is a `PublishesChatActivity` gets a `chat/activityChanged` on the run's main chat every `heartbeat` seconds ("Running 2 steps") with `_meta['ahp-py/flow'] = {'heartbeat': {'running', 'tick'}}` (ticks count from 1). The activity is cleared when the run ends. This keeps `ahp-client`'s default 300 s `idle_timeout` from firing on a silent step; the README no longer advises `idle_timeout=None`. `tests/integration/test_heartbeat_run.py`.

### Added — idle watchdog and retry_empty (M16)

- `idle_timeout` is allowed on in-process and fleet providers too (remote keeps its 600 s default; the others have no watchdog unless set). `bridge.Watchdog` (`start`, `touch`, `pause`, `resume`, `stop`) fires once after that many silent seconds; `TurnTee(watchdog=)` touches it on every forwarded event (text, reasoning, tool calls, notifications, usage, failure) and pauses it while a confirmation or input request is open. `ProviderDispatcher` cancels the turn (inner cancel reason `idle timeout`, not a skip) and the call fails with kind `timeout`; the fleet wait loop samples the node session at least twice per `idle_timeout` and treats a changed row status, or a changed `activity` (ahp-gateway's fingerprint of the node session's chat, on every `wait_for_sessions` row), as activity, `waiting` as a pause, and stops the node session on expiry (`tests/integration/test_fleet_idlewatch.py`). `ProviderConfig.retry_empty` (all kinds, default 0): `RoutingDispatcher` dispatches again while the reply is empty (no text, or no value for a schema), summing usage and cost into one `AgentResult`; a retry's main-chat tool call is `agent-<n>-a<k>`; still empty fails with kind `empty`. `tests/integration/test_idlewatch.py`, `tests/integration/test_retryempty.py`.

### Added — per-user quotas (M16)

- `flow.toml` `[quotas]` (`QuotaLimits`, `FlowConfig.quotas`): `tokens_per_day`, `tokens_per_run`, `cost_per_day`, `cost_per_run`. `engine/quota.py`: `QuotaLedger` keeps each principal's day totals in `<state_dir>/quotas.json` (written atomically, a missing or corrupt file starts empty, a stale day counts as 0) and `RunQuota` is one run's view, passed as `RunOptions.quota`. The provider builds one ledger when `[quotas]` is set and charges the turn's principal; runs with none share the '' bucket. `tests/unit/test_quota_ledger.py`, `tests/integration/test_quota_hosted.py`.

### Added — [limits] and call timeouts (M16)

### Added — hard budget cap (M16)

- `RunOptions.reserve` (default `None`: the mean output tokens of the run's finished live calls, else 0; `reserve=0` turns reservations off): with `budget_total` set, `admit` reserves it per live call and refuses a call once spent plus the other calls' reservations reaches the budget, so parallel calls cannot overshoot. A sequential script is unaffected, since admission counts only other in-flight calls' reservations (`tests/unit/test_reservemean_default.py`). `engine.usage_reporter()` gives a dispatcher the hook through which a running call reports its cumulative usage (the Scheduler binds it around `create_task`, like the dispatch report); `TurnTee(on_usage=)` feeds it from usage reports, counting request-scoped readings until a turn report covers them, and `ProviderDispatcher` reports through it. When a counter, live usage included, passes its limit, or the wall budget runs out, the Scheduler stops every call in flight: each is journaled as an error of kind `budget` with the output it had used, and its `agent()` throws like a refused call. A `budget` record is not replayed on resume, so the call runs live. `tests/unit/test_livestop_reserve.py`, `tests/unit/test_livestop_engine.py`, `tests/integration/test_livestop_hosted.py`.

### Added — budget counters (M16)

- `RunOptions.input_budget`, `cost_budget`, `count_cache` (default true: cache reads count as input) and `wall_budget` (seconds; unlike `timeout` it kills nothing: later steps stop in-flight calls and refuse new ones) beside `budget_total`. `Budget` keeps named counters (`COUNTERS`: output, input, cost, wall) and `refusal()` names the first exhausted one; the output-token message is unchanged. `AgentResult.cost_usd` and a `cache_read_tokens` usage key feed them. `engine/usage.read_usage` reads a turn report properly (Claude's `turnTotals`, cache reads apart from input, `costUsd` or ACP's USD `acpUsage.cost`), and `TurnTee` uses it: a request-scoped report (`ahp_protocol.ext.usage`) is forwarded but not summed. None of the new options are journaled (a resume uses the resuming run's values), and a cached replay adds only its output tokens (known limit). `tests/unit/test_budgetctr.py`, `tests/unit/test_budgetctr_usage.py`.

### Added — error kinds (M16)

An error agent record in the journal carries `kind` (ok and null records and pre-M16 records are unchanged; old readers ignore it). `tests/unit/test_errkind_table.py`, `tests/unit/test_errkind_journal.py`. ### Added — Commit and Discard reasons (M15)

- A worktree changeset has a Commit operation (`COMMIT_OPERATION`): it commits the agent's changes on a new branch and removes the worktree, or with `params.apply` commits just those paths on the working tree. `params.message` sets the message (default: the call's label, else the prompt's first line up to 72 characters, else `flow: run <runId> step <ordinal>`, masked). A rename or delete committed with `params.apply` is committed whole (`--no-renames`), and the user's own staged changes stay out of the commit. The `Flow-Principal:` value has CR, LF and control characters removed. Never pushes. `[changesets]` in flow.toml sets `branch` (default `flow/{runId}-{ordinal}`) and `trailer` (a `Flow-Principal:` line).
- Discard takes an optional `params.reason` (also on a changeset that survived a restart): it is masked, logged, shown in the changeset's description, posted as a notification turn on the worker chat and queued (`WorktreeChangesets.take_notes`) as a `[discarded: ...]` line before the named chat's next prompt.

### Added — approval rules and flow policy (M15)

- `[policy]` (the `ahp-host` `ToolPolicy` table) and `[[approvals.rules]]` (`tool`, `read_only`, `provider`, `phase`, `persons`, `action`) in flow.toml answer an in-process worker's tool confirmations (`approvals.Approver`, wired through `TurnTee(approver=)` and `ProviderDispatcher(principal=)`). Security decision: the policy is checked first and always wins; a rule can never allow what the policy denies or asks, or a call the inner provider's policy asked about. Remote relays are always prompted.
- Security decision: the flow `[policy]` is also handed to an in-process provider whose factory takes a named `policy` keyword (`ahp_host_claude:from_config`, `ahp_host_acp:from_config`), folded into the provider table's own `policy` as a check (a deny from either wins), so an approve-all that stops a worker asking does not switch it off. A provider configured by a file path is given it too and combines it with its file's `[policy]` (`from_config`). Fleet and remote workers never get it (documented).
- Security decision: a `read_only` rule ignores a hint the agent supplied itself (ACP's `kind`, `read_only_from_agent`) unless it sets `trust_agent_hints = true`. A call filed as a read or write whose path cannot be read (an ACP read with only `locations`, now read too) is judged as one with no path, which asks when there are path rules.

### Added — remote approvals (M15)

- A remote call's approvals and questions are relayed to its worker chat (`RemoteOut.confirm` and `ask`, with `RemoteConfirmation`, `RemoteDecision`, `RemoteQuestion` and `RemoteAnswer`): the answer, a denial's reason and suggestion included, goes back to the remote session. An open request pauses `idle_timeout` (a late answer still lands); a remote turn that goes silent still times out. A remote provider's optional `approval_timeout` bounds a relayed request: an unanswered one fails the call, naming the provider and the setting, and stops the remote turn. The relayed copies are masked. A bare dispatcher still cannot answer and times out as before.

### Security

- Gate options are re-checked by the host (`engine/gates.options_error`, in `GateRunner.issue`): a script could make the JS runner send options its own checks never saw (a `toJSON` on `choices` or `diff`, a replaced `JSON.stringify`), and the host passed them to the main chat's form unchecked. Unknown keys, malformed `choices`/`schema`/`diff`, and `choices` with `schema` are now refused before a gate ordinal is taken; the verb throws the host's reason. An adversarial audit of the gate verbs (`test_flowext_sandbox_escape`) found no realm escape: their values, promises, errors and prototype chains stay in the script realm, answers cross as JSON only, and a JS child's verbs are its own.
- Attached file paths (`opts.x.attach`) are resolved (symlinks followed) and must be regular files inside the run's working directories; anything else fails the call before a worker chat opens.
- `[workflows] python_sources` can never include `client`: a client cannot supply a `.py` workflow, and the config is refused.
- A client-published workflow listing is trusted for names only as plain file names: an entry with a path separator or `..` (`../x.js`) is skipped, so the read URI never leaves the plugin's `workflows/`. The 1 MiB cap bounds what is kept, not what the client sends (the plugin read API returns the whole file).
- `.py` workflows are arbitrary code on the host, so they load by default only from the host and user sources: `[workflows] python_sources` in flow.toml (default `["user", "host"]`) must include `"workspace"` for a project's `.claude/workflows/*.py`, and client-published plugins never supply one.
- Credential masking before publishing (plan §4.9): a secret printed or returned by an inner agent is masked in the worker chat's text, reasoning, tool calls and results, structured calls (the `StructuredOutput` input and accepted result), approval and input prompts (`ToolConfirmation`, `InputRequest`), step results, `log()` lines, run errors, the `agent()` return and the journal (`[redact]` in `flow.toml`). Values under secret-named keys (`password`, `token`, `api_key`...) are masked at any depth. The inner agent's own view (prompts sent, replies, tool results and answers returned to it) is untouched. The run's own `canvas()` title and URL are masked before `canvas_set`. Known gaps: terminals and background work opened through `ScopedPublisher`, a secret split across a tool-call boundary mid-stream, and the best-effort builtin list (no `key=value` values under 8 characters, URL userinfo or `sk-` keys); the first wait for the after-publishing layer (§4.9, M9).
- `ScopedPublisher` contains an inner session: a `chat=` it passes is honoured only for its worker chat or a tool chat it opened itself. A foreign chat (the run's main chat, another worker) is never reached: config changes, external turns and changesets naming one are dropped, and canvases, terminals, background work and tool chats are redirected to the worker chat. `dropped` is a bounded deque (`dropped_counts` keeps totals by kind), so progress spam cannot grow it.
